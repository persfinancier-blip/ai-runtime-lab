# LAB-010 audit correction

Date: 2026-08-18

The first remote patch audit found a lifecycle defect before integration.

## Defect

When validation passed but the audit discovered a regression, the coordinator moved the task back to `PATCHED` while leaving `audit_regression` in the unresolved failure set. `patch()` only accepted `REPRODUCED`, so the task could neither create a corrected artifact version nor ever satisfy the final `not task.failures` completion gate.

This meant the implementation modeled rejection correctly but not recovery, contradicting the intended end-to-end loop.

## Correction

- `patch()` now accepts both first patching from `REPRODUCED` and repatching from `PATCHED`.
- reparable failures are removed from the unresolved blocker set when a new artifact version is produced;
- `failure_history` preserves prior failures for taxonomy/audit instead of erasing them;
- failure taxonomy counts historical failures when available;
- a new deterministic test executes `audit regression -> repatch -> revalidate -> clean reaudit -> accept` and asserts that the regression remains in history while no longer blocking completion.

## Re-validation

Observed locally after correction:


`python -m compileall -q experiments/software_engineering_loop` also completed successfully.

This audit result strengthens the main finding: a full lifecycle must model not only gates that reject bad work, but also explicit recovery transitions that distinguish historical incidents from currently unresolved blockers.
