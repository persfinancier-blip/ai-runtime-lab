# Ecosystem convergence evidence authenticity, cohort inventory, enforcement cutover, legacy decommission — v1

Status: `ECOSYSTEM_CONVERGENCE_EVIDENCE_AUTHENTICITY_COHORT_INVENTORY_ENFORCEMENT_CUTOVER_DECOMMISSION_V1_FROZEN`

Date: 2026-09-08

## Context

The preceding rebootstrap-convergence contract separated three facts that must never be collapsed: publishing a new trust lineage, relying-party acceptance of it, and ecosystem convergence. It also established that an open/unbounded client population cannot honestly prove universal client migration; the meaningful terminal property is enforcement cutover plus explicit quarantine of residual legacy clients.

That leaves an evidentiary problem. Migration dashboards, heartbeat telemetry, inventory exports, gateway logs and control-plane health signals are themselves mutable observations. If they are allowed to define the migration denominator or to prove their own completeness, a disappearing verifier can make the percentage improve, an attacker can replay stale "all green" telemetry, and a nominally retired gateway/replica can continue authorizing old-lineage consequential requests outside the measured path.

This contract freezes how convergence evidence is authenticated, how verifier cohorts are enumerated without denominator laundering, how enforcement points prove cutover, how decommission is demonstrated, and how contradictions are handled.

## Primary-source findings

### RATS: telemetry is Evidence, not automatically truth

RFC 9334 defines Evidence as claims generated by an Attester and appraised by a Verifier. Evidence can include configuration, measurements and telemetry. The Relying Party consumes an Attestation Result under its own appraisal policy. The architecture explicitly requires evidence to be securely associated with the target environment and discusses freshness using timestamps, nonces or epoch IDs. This supports a hard separation between raw migration telemetry and an authority-bearing appraisal result.

Source: RFC 9334, Remote ATtestation procedureS (RATS) Architecture, January 2023: https://www.rfc-editor.org/rfc/rfc9334.html

### SCITT: signed statements gain auditable registration through receipts

RFC 9943 defines Signed Statements as identifiable/non-repudiable issuer statements and Transparent Statements as signed statements carrying registration receipts from a transparency service. Receipts prove registration in an append-only verifiable data structure. This is a useful donor for making cutover/decommission attestations independently auditable instead of trusting a mutable dashboard/database row.

Source: RFC 9943, An Architecture for Trustworthy and Transparent Digital Supply Chains, August 2025: https://www.rfc-editor.org/rfc/rfc9943.html

### NIST CM-8: inventory must reflect the actual system and avoid duplicate accounting

NIST SP 800-53 Rev. 5.1 CM-8 requires a system-component inventory that accurately reflects the system, includes all components, avoids duplicate accounting, has sufficient granularity for tracking/reporting, and is reviewed/updated. This supports treating cohort membership as governed configuration/history, not as the set of clients that happened to report during the current telemetry window.

Source: NIST SP 800-53 Rev. 5.1, CM-8 System Component Inventory: https://csrc.nist.gov/pubs/sp/800/53/r5/upd1/final

### SPIFFE: trust distribution has explicit refresh semantics and domain binding

SPIFFE Federation requires retrieved bundles to remain bound to their trust domain, recommends advance publication of new keys, expects periodic polling/refresh, and warns that key-removal timing affects revocation/convergence. This is a useful donor for distinguishing configured population, fetched state, freshness and effective enforcement state.

Source: SPIFFE Federation specification: https://spiffe.io/docs/latest/spiffe-specs/spiffe_federation/

## Core boundaries

`TELEMETRY_OBSERVED != TELEMETRY_AUTHENTICATED != CLAIM_APPRAISED != AUTHORITY_PROVEN`

`REPORTING_CLIENTS != REQUIRED_COHORT_DENOMINATOR`

`CONTROL_PLANE_CONFIGURED_CUTOVER != ENFORCEMENT_POINT_EFFECTIVE_CUTOVER`

`NO_LEGACY_TRAFFIC_OBSERVED != LEGACY_AUTHORITY_DECOMMISSIONED`

Absence of observations is not positive evidence that an authority surface no longer exists.

## Threat model

Assume migration from old lineage `L0` to rebootstrap lineage `L1` is underway. Attack/failure cases include:

- a stale verifier stops reporting and silently disappears from a dashboard denominator;
- a telemetry collector or database replays an older all-green report;
- two collectors see different cohort states;
- a verifier signs an acceptance report but is actually attached to a stale local trust bundle or stale enforcement replica;
- a gateway reports `L1` current but an old cache, worker, region or failover listener still accepts `L0` consequential authority;
- a decommissioned endpoint remains reachable through stale DNS, load-balancer membership, direct address, service discovery or offline replica activation;
- an inventory controller deletes a missing component instead of preserving it as unresolved/offline;
- the same physical verifier is counted under several logical identities;
- replacement instances are counted without proving which old instance they supersede;
- a monitoring system's own compromised credentials produce valid-looking success events.

The goal is not perfect omniscience. The goal is to make the strongest completion claim justified by authenticated, freshness-bounded, contradiction-aware evidence and to fail closed when required population or enforcement evidence is missing.

## Frozen data model

### `VerifierCohortInventoryV1`

A policy-governed inventory snapshot must bind:

- `inventory_generation`;
- `migration_generation`;
- `lineage_transition_id`;
- each required verifier/cohort stable identity;
- administrative/control domain;
- operation classes the cohort can authorize;
- criticality/weight;
- expected reporting/attestation channel;
- owner/registration authority;
- lifecycle state: `ACTIVE`, `OFFLINE_EXPECTED`, `QUARANTINED`, `REPLACED`, `DECOMMISSION_PENDING`, `DECOMMISSIONED`;
- predecessor/successor relation when replaced;
- `included_from_generation` / optional `removed_after_generation`;
- inventory-policy digest;
- canonical digest and authority signatures/quorum.

A cohort does not leave the denominator because it failed to report. Removal requires an explicit lifecycle transition with evidence.

### `MigrationEvidenceEnvelopeV1`

Every evidence item used toward convergence must bind:

- producer/attester identity;
- subject identity (`verifier`, `gateway`, `cache`, `replica`, `region`, etc.);
- evidence class;
- observed `trust_lineage_id`;
- accepted rebootstrap/migration generation and root/bundle digest;
- operation-class enforcement claims;
- nonce, epoch ID or trusted-time freshness data;
- software/configuration/measurement identity when available;
- collector/verifier identity;
- appraisal-policy digest;
- resulting state;
- canonical digest/signature;
- optional transparency-registration receipt/checkpoint.

Raw telemetry lacking an authenticated envelope may inform diagnostics but cannot satisfy a convergence threshold.

### `EnforcementCutoverAttestationV1`

Per effective enforcement point:

- stable enforcement-point identity;
- topology/control-domain identity;
- migration generation / `L1` digest;
- exact prohibited `L0` operation classes;
- exact accepted `L1` operation classes;
- rule/config digest;
- running implementation/build digest when measurable;
- challenge nonce/epoch/freshness;
- positive `L1` probe result;
- mandatory negative `L0` probe result for consequential authority;
- downstream/upstream path identity if a proxy/mesh is involved;
- attester/verifier identities and appraisal-policy digest;
- transparency receipt / append-only publication reference.

A config-file statement alone is insufficient. At least one policy-designated effective-path test must demonstrate that an `L0` consequential request is rejected after cutover.

### `LegacyDecommissionProofV1`

For each old-lineage authority surface:

- stable identity and all known network/service-discovery aliases;
- last authority-bearing role;
- replacement or retirement reason;
- final accepted migration generation;
- removal from active routing/service discovery/load-balancer membership;
- credential/key/capability revocation or quarantine state;
- process/replica shutdown evidence where applicable;
- failover/DR membership state;
- direct-address negative reachability/admission probe where policy requires;
- archival disposition of historical verification material;
- decommission generation;
- signed attestation + appraisal result;
- transparency registration reference.

`DECOMMISSIONED` is an evidence-backed lifecycle state, not a missing heartbeat.

### `EcosystemConvergenceEvidenceSetV1`

Must bind:

- exact `VerifierCohortInventoryV1` generation;
- migration/rebootstrap package digest;
- all required fresh `MigrationEvidenceEnvelopeV1` items;
- all critical `EnforcementCutoverAttestationV1` items;
- pending/offline/quarantined population explicitly retained in denominator;
- decommission proofs for surfaces removed from required active population;
- contradictions/disputes;
- freshness frontier;
- completion-policy digest;
- terminal classification.

## Inventory and denominator semantics

### 1. Membership is governed, not observational

The denominator is derived from an authenticated inventory generation plus explicit lifecycle transitions. A telemetry query such as `seen within 24h` is never the authoritative membership definition.

### 2. Missing becomes `UNKNOWN/OFFLINE`, not absent

If an `ACTIVE` required cohort misses its reporting or freshness bound, it moves to `STALE_OR_OFFLINE_REQUIRED`, remains in the denominator, and prevents any completion claim whose policy requires that cohort.

### 3. Replacement is explicit

A new verifier does not automatically replace an old one because it has the same hostname, label or role. `REPLACED` requires a predecessor/successor transition authorized by the inventory owner and, for critical authority-bearing cohorts, evidence that the predecessor can no longer perform prohibited operations.

### 4. Identity deduplication is required

Counting aliases of one underlying verifier/control domain as independent migrated entities is prohibited. Cohort policy must define the stable identity and independence domain used for threshold/convergence accounting.

### 5. Population scope must be stated

For a closed managed fleet, completion may quantify every required inventory member. For open/unbounded clients, the inventory covers only policy-designated controlled/critical cohorts; residual external clients remain explicitly outside universal convergence claims and are controlled through server-side enforcement cutover.

## Evidence authenticity and freshness

### 1. Raw telemetry cannot grant authority

Metrics, logs and dashboards are observational inputs. They become usable convergence evidence only after authentication, subject binding, freshness appraisal and policy evaluation.

### 2. Challenge freshness for high-value cutover evidence

For critical enforcement points, prefer nonce- or epoch-bound evidence so replay of an old successful attestation cannot satisfy the current migration generation. RFC 9334's nonce/epoch patterns are direct donors.

### 3. Evidence producer and subject are distinct

A collector saying "gateway X is migrated" is not equivalent to gateway X (or its trusted attesting environment) producing evidence about its own effective state. `MigrationEvidenceEnvelopeV1` records both producer and subject.

### 4. Appraisal policy is part of the result

A positive result is meaningful only relative to the exact policy used to judge it. Therefore the appraisal-policy digest is bound into the evidence set, and policy rollback/equivocation is separately detectable.

### 5. Transparency protects against silent rewrite

Critical cutover, inventory-generation and decommission statements should be registered into the existing append-only publication/transparency layer and carry receipts/checkpoints. This does not prove the statement true by itself; it proves which statement was published and prevents easy retrospective deletion/rewrite.

## Enforcement-cutover proof

A migration can be declared operationally cut over only when every policy-designated consequential enforcement path is represented by a current attestation.

Required proof dimensions:

1. **Configuration identity** — the rule/config claims to reject `L0`.
2. **Running identity** — the attested implementation/replica is the one expected to enforce the rule.
3. **Positive path** — a valid `L1` operation reaches the expected result.
4. **Negative path** — an otherwise equivalent `L0` consequential operation is rejected.
5. **Freshness** — evidence is tied to the current migration generation and a current nonce/epoch/time bound.
6. **Topology coverage** — all authority-bearing ingress/failover/region/cache/worker paths designated by policy are included.

A negative `L0` probe is intentionally required: declarative configuration is not proof that the effective data plane loaded that configuration.

## Caches, replicas, failover and hidden paths

The inventory must separately enumerate any component capable of independently accepting/authorizing a consequential operation. Examples:

- API gateways and regional gateways;
- policy sidecars/meshes if they make authority decisions;
- caches that can serve authority-bearing signed decisions beyond the cutover frontier;
- asynchronous workers consuming queued old-lineage authorizations;
- database/read replicas that can be promoted and then accept writes;
- DR/failover control planes;
- compatibility proxies that translate old-lineage requests.

A passive cache that cannot authorize or produce post-cutover effects may be classified differently, but the rationale must be explicit.

## Legacy decommission semantics

### 1. No heartbeat is not decommission proof

A silent host is `OFFLINE/UNKNOWN` until an authorized lifecycle transition plus decommission evidence exists.

### 2. Routing removal is necessary but not sufficient

Removing an old endpoint from DNS/load balancing does not prove direct reachability, stale service discovery, failover promotion, queued work or old credentials cannot still produce effects.

### 3. Credentials/capabilities must be fenced or revoked

If an old component retains a capability accepted by downstream services, physical shutdown alone is weak evidence. Downstream enforcement should reject the old lineage/generation regardless of whether the process later reappears.

### 4. Historical verification material is preserved

Decommission removes current authority, not historical evidence. Public keys/checkpoints needed to verify pre-cutover artifacts remain archived under the historical-verification contract.

## Contradiction semantics

Conflicting evidence does not average out.

Examples:

- verifier reports `L1_CURRENT`, gateway negative probe shows `L0` still accepted;
- control plane reports gateway retired, external reachability/admission probe shows it still authorizes;
- inventory says component replaced, predecessor still produces fresh authority-bearing evidence;
- two authenticated collectors report different effective migration generations for the same enforcement identity.

For any required critical component, a credible contradiction yields `CONVERGENCE_EVIDENCE_CONFLICT_NO_COMPLETION` until reconciled. A newer timestamp, majority telemetry source or dashboard health score cannot silently override the contradictory evidence.

## Frozen classifications

- `CONVERGENCE_PROVEN_FOR_BOUNDED_INVENTORY` — every required member of a closed inventory has fresh accepted-current evidence and all critical enforcement paths prove cutover.
- `ENFORCEMENT_CUTOVER_COMPLETE_WITH_RESIDUAL_LEGACY_CLIENTS` — all policy-designated enforcement points reject prohibited old-lineage authority, while open/unbounded external clients may remain stale.
- `CONVERGENCE_INCOMPLETE_REQUIRED_COHORT_STALE` — at least one required cohort lacks fresh evidence.
- `CONVERGENCE_INCOMPLETE_ENFORCEMENT_UNPROVEN` — client acceptance may look complete but at least one authority-bearing data-plane path lacks effective cutover proof.
- `CONVERGENCE_EVIDENCE_CONFLICT_NO_COMPLETION` — independently credible evidence conflicts.
- `DECOMMISSION_INCOMPLETE_REACHABLE_OR_AUTHORIZED` — a retired component/path is still reachable with effective prohibited authority.
- `INVENTORY_INTEGRITY_UNKNOWN` — inventory generation/provenance cannot be authenticated.

## Fraud / contradiction proofs

1. `DENOMINATOR_LAUNDERING_PROVEN` — required cohort removed solely because telemetry disappeared.
2. `TELEMETRY_REPLAY_PROVEN` — stale migration evidence reused as current.
3. `SUBJECT_BINDING_FAILURE_PROVEN` — evidence for one component accepted as evidence for another.
4. `DUPLICATE_COHORT_COUNTING_PROVEN` — one failure/control domain counted as multiple independent migrated entities.
5. `FALSE_REPLACEMENT_PROVEN` — successor counted while predecessor remains current-authority capable.
6. `CONFIG_EFFECTIVE_STATE_DIVERGENCE_PROVEN` — configured cutover says reject while effective path accepts prohibited `L0`.
7. `LEGACY_AUTHORITY_AFTER_DECOMMISSION_PROVEN` — a decommissioned identity produces accepted consequential authority.
8. `STALE_FAILOVER_PATH_PROVEN` — failover/DR path still accepts old-lineage authority after primary cutover.
9. `CONVERGENCE_REPORT_EQUIVOCATION_PROVEN` — conflicting signed evidence sets for same inventory/migration generation.
10. `OBSERVABILITY_AS_AUTHORITY_PROVEN` — monitoring state is used directly to grant/restore authority without independent enforcement policy.
11. `DECOMMISSION_BY_ABSENCE_PROVEN` — missing heartbeat/log entry is treated as retirement evidence.
12. `APPRAISAL_POLICY_ROLLBACK_PROVEN` — older/weaker evidence-appraisal policy is replayed to turn a failed cutover into PASS.

## RED-first matrix

### Inventory / denominator
1. required active verifier reports fresh -> counted migrated;
2. required verifier stops reporting -> remains denominator, becomes stale;
3. dashboard query excludes stale verifier -> completion still blocked;
4. authorized decommission transition + proof -> removed after generation boundary;
5. same verifier under two aliases -> deduplicated;
6. two verifiers in same declared failure domain -> not independent quorum members;
7. new replacement appears, predecessor unretired -> both remain relevant;
8. valid predecessor retirement + successor activation -> replacement accepted;
9. inventory generation rollback -> reject;
10. conflicting inventory generations at same sequence -> dispute.

### Evidence authenticity / freshness
11. unsigned telemetry claims L1 -> diagnostic only, no convergence credit;
12. signed subject-bound fresh evidence -> eligible for appraisal;
13. evidence validly signed but wrong subject -> reject;
14. old nonce replay -> reject;
15. old epoch after migration-generation advance -> reject;
16. attestation result expired -> stale;
17. collector identity valid but appraisal policy unknown -> no convergence credit;
18. appraisal-policy digest rollback -> reject/dispute;
19. transparent receipt missing where policy requires -> no completion credit;
20. statement registered but evidence content fails appraisal -> still fail.

### Enforcement cutover
21. config says L0 reject, negative probe confirms -> pass dimension;
22. config says reject, L0 negative probe unexpectedly succeeds -> fail;
23. L1 positive probe fails -> cutover incomplete;
24. primary gateway passes, regional gateway untested -> incomplete;
25. all active gateways pass but DR path stale -> incomplete;
26. cache can independently authorize stale result -> must be inventoried/tested;
27. passive non-authorizing cache -> may be excluded with explicit policy;
28. async worker accepts queued pre-cutover L0 authorization after forbidden frontier -> fail;
29. missing lineage ID on consequential request -> enforcement rejects;
30. compatibility proxy reauthorizes only under scoped L1 bridge -> allowed.

### Decommission
31. host silent only -> not decommissioned;
32. removed from DNS but direct endpoint accepts L0 -> incomplete;
33. removed from load balancer but stale discovery path accepts -> incomplete;
34. process shut down but downstream old credential still accepted -> incomplete;
35. downstream generation fence rejects old credential -> authority decommission dimension passes;
36. decommissioned verifier comes back online -> current authority remains rejected;
37. old historical public key retained for verification -> allowed;
38. old private/current authority capability retained and accepted -> fail;
39. replica marked retired but promotable with stale policy -> incomplete;
40. independently verified replica removed from promotion set + old lineage rejected downstream -> pass.

### Contradictions / completion
41. client acceptance 100%, one gateway still accepts L0 -> no completion;
42. all critical gateways reject L0, open external population includes stale clients -> `ENFORCEMENT_CUTOVER_COMPLETE_WITH_RESIDUAL_LEGACY_CLIENTS`;
43. closed inventory all members fresh + enforcement cutover pass -> `CONVERGENCE_PROVEN_FOR_BOUNDED_INVENTORY`;
44. one required cohort offline -> incomplete;
45. collector A PASS / independent probe B FAIL -> conflict/no completion;
46. newer PASS does not erase unresolved credible FAIL -> reconcile first;
47. no legacy traffic observed for long window -> not decommission proof;
48. decommission proof published then later contradictory authority event appears -> reopen dispute;
49. monitoring database restored to old all-green snapshot -> inventory/evidence generation rollback detected;
50. completion report itself replayed after a newer migration/inventory generation -> reject as stale.

## Implementation implications for LAB-093 family

When exact source execution is available, add tests before production refactors. The design likely needs:

- immutable/stable IDs for verifier cohorts and enforcement points;
- authenticated inventory generations separate from heartbeat/telemetry storage;
- subject-bound evidence envelopes with nonce/epoch freshness;
- a policy appraiser producing explicit attestation results rather than treating raw metrics as truth;
- mandatory negative old-lineage admission probes for consequential enforcement paths;
- explicit lifecycle transitions for replacement/decommission;
- append-only publication of inventory, cutover and decommission statements;
- contradiction state that blocks completion but does not automatically revoke historical evidence;
- server-side generation/lineage fencing as the final authority boundary even when observability is unavailable.

Do not let convergence telemetry itself mutate trust roots, migration generations or operation admission. Observability can prove or disprove that an independently configured authority policy is effective; it must not become the authority policy.

## Decision

Freeze `ECOSYSTEM_CONVERGENCE_EVIDENCE_AUTHENTICITY_COHORT_INVENTORY_ENFORCEMENT_CUTOVER_DECOMMISSION_V1_FROZEN`.

Migration completion is an evidence claim over a governed population and effective authority paths. Missing telemetry remains missing evidence; it does not shrink the population. Declarative configuration is not effective cutover proof. A retired legacy component is considered harmless only when its lifecycle transition is authenticated and the consequential authority it previously held is independently fenced/rejected. Any credible contradiction in a required path blocks a completion claim until reconciled.
